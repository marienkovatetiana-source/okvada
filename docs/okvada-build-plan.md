### 2.4. Решения (20 Nov) и открытые вопросы
Решено: WordPress — после утверждения заказчиком; сначала EN до продакшена, потом DE; контент пока правит дизайнер, затем заказчик сам; заявки уходят заказчику на почту; аналитика — Google Analytics (грузить только после согласия в cookie-баннере, Consent Mode). Открыто: что значит «bundle rewrite», в какой репозиторий и куда деплоим, какой хостинг, ID Google Analytics.

Исходные вопросы (для истории):
1. WordPress — какой подход: (а) своя тема на PHP по этим HTML, (б) Gutenberg-блоки/ACF, (в) оставить статикой на хостинге? От этого зависит структура HTML (`index.html` сейчас без `<html>/<head>/<body>` — их добавляет артефакт).
2. Нужна ли немецкая версия на запуске.
3. Кто редактирует контент после запуска (требования к CMS: кейсы, вакансии, FAQ).
4. Куда уходят заявки и кто их обрабатывает; обещание ответа («reply time») на Thank you — реальное ли.
5. Какие аналитики/CRM подключаем.

## 3. План работ

## 4. Правила на время работы (остаются в силе)
Чистые HTML / CSS / JS, mobile-first (375 → 768 → 1200), только токены из `css/tokens.css`, без `!important` вне reduced-motion, иконки из спрайта, анимации только из Motion в `docs/okvada-final-ui-decisions.md`, ничего «от себя» в тексты и элементы, в конце каждой задачи — список отклонений и что не проверено.
