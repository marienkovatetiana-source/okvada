## 0. Что уже хорошо
- Отступы секций, поля, контейнер — только токенами (`--section-*`, `--gutter`, `--container`), сырых значений на корнях секций нет.
- Шрифтов 3 (Barlow / Inter / JetBrains Mono) — в лимите. `!important` только в reduced-motion.
- Сырых цветов в CSS всего 14 вхождений (почти все градиенты в `home.css`), остальное — `var(--color-*)`.
- Проблемы: токенов цвета 22 (лимит 8–12), теней 6 + 4 сырых (лимит 1–2), размеров текста 18 разных (лимит 6–8), отступов 10 шагов + ~25 сырых значений, радиусов 6 + сырые.

## 3. Контраст (посчитано по формуле WCAG)
Проходит: navy на canvas/muted/surface 13.7–15.4; ink-muted 6.3–7.1; teal-text 4.7–5.3 (на canvas 4.96, на muted 4.73); белый на navy 15.4; on-navy-muted на navy 7.6, на navy-raised 6.3, на navy-deep 8.7; teal на navy-deep 9.0 (текст на тёмном — можно); danger на surface/canvas 5.2 / 4.8; navy на teal 7.9; success как точка (не текст) 3.9–4.1 ≥ 3.
**Не проходит:**
- **Рамка `.select` (components.css:664) и рамка `.lead-form`** — `--color-line` на белом 1.3 : 1, для границы поля нужно ≥ 3 : 1. Рамка `.select` — граница интерактивного поля. Для `.lead-form` (контейнер, не поле) допустимо, это декор.
- Яркий teal `#00d1b2` на светлом 1.8–1.95 — как и задумано, только точки и линии. Проверил выборочно по `color: var(--color-accent-default)` (about, careers) — это тёмные панели; **все 32 использования по контексту не проверял**.
- Разделители line (1.2) — декор, WCAG не требует, но это «границы» по твоему пункту. Оставляю как есть и пишу сюда прямо.

## 4. Было → стало, почему
| Было | Стало | Почему |
|---|---|---|
| 22 токена цвета | 13 | лимит 12; одно значение — один токен |
| `text-primary`, `bg-inverse`, `border-strong`, `text-on-accent` (все `#0b2545`) | `--color-navy` | идентичное значение |
| `text-on-inverse` + `bg-surface` (оба `#fff`) | `--color-surface` | идентичное значение |
| `bg-muted` + `text-on-inverse-soft` + `#edf2f7` | `--color-muted` | идентичное / ближайшее (`#edf2f7` ≈ `#eef2f7`) |
| `border-line` + `bg-hover #dce3ec` | `--color-line` | Δ 1 единица |
| `accent-default`, `accent-on-inverse #4fddc7`, `#2adcc1` | `--color-teal` | три почти одинаковых teal; `#4fddc7` на navy-deep даёт 10.4 вместо 9.0 — читаемость остаётся |
| `border-on-inverse #2a4466` | `--color-navy-raised` | 1 использование, рамка на тёмном |
| `--color-error #c0392b` | удалён | 0 использований, дубль danger |
| `--color-bg-canvas-clear` | убран; градиент пишется от canvas с alpha | производное, не цвет |
| 6 теней + 4 сырых | 2 | лимит 1–2 |
| радиусы `sm 4`, `6px`, `3px`, `50%` ×11 | md / full | 4 → md (2 хвоста чат-пузырей + 2 мелких); `50%` → full (все квадраты — точки/круги) |
| 18 размеров текста | 8 + декор | лимит 8; 72 и hero 80 → 72, hero mobile 40 и `52` → 44 |
| планшет 60 / 48 / 36 / 18 | 56 / 44 / 44 / 20 | в Figma их нет; сводятся к ступеням шкалы |
| 12 значений line-height | 5 + декор | 1.04 / 1.02 / 1 → 1.05; 1.15 → 1.1 |
| `--space-4xl` 96, `--space-5xl` 128 | `--section-desktop`, `--section-system-bottom` | это размеры секций, не шаги; шагов остаётся 8 |
| сырые отступы 6 / 10 / 14 / 15 / 18 | 8 / 8 или 12 / 16 / 16 / 16 | Δ ≤ 2 px |
| `max-width` 400 / 420 / 440 / 454 | `--measure-sm` 420 | близкие значения |

Остаются сырыми осознанно (в Figma так): hero сверху 170 / 104, About gap 28 (2×), Why Okvada inset 14 (из `docs/okvada-final-ui-decisions.md`), декор hero и 404.

3. **Сырые 20 px (21×), 28 (10×), 40 (7×)**: они в Figma. Оставить их сырыми (тогда «шагов отступа» 8, но значения вне токенов) или привязать к шагам 24 / 24 / 48 — высоты секций сдвинутся (в audit-файле они совпадали с макетом ±5 px). Рекомендую пока не трогать.

## 6. План шага 2 (после «да»)
Переименование токенов делается скриптом по всем 11 CSS; старые имена в `tokens.css` не оставляю, иначе будут дубли. Порядок: tokens.css → base → components → страницы; после каждого файла сравнение значений до / после (computed style на 375 и 1440). Без `!important`, без новых свойств.

## 7. Результат шага 2 (выполнено, 20 Nov)
Сделано по рекомендациям из п. 5. Исходные CSS до замены сохранены вне проекта (scratchpad `css-orig`). Позже в проекте появился git (ветка main, remote origin); изменения шага 2 пока не закоммичены.

Отличия от плана выше (честно):
- **Сырые отступы 6 / 10 / 14 / 15 / 18 НЕ сведены** к шагам. Проверка показала, что snap 10 → 12 даёт +22 px на mobile Services (ряды specs), а mobile должен держаться макета (±3 px). Остались сырыми. Токенами заменены только точные значения (4 / 8 / 12 / 16 / 24 / 32 / 48 / 64).
- `eyebrow` оставлен с `line-height: normal` (1.4 дал бы +1.3 px на каждый).
- `letter-spacing: 0` в careers.css оставлен (сброс, не значение дизайна).
- Размеры текста — **8 статичных токенов** (`--text-data … --text-display`), без отдельных mobile-значений; mobile / tablet / desktop выбираются в `.t-*` (base.css) из тех же токенов. Это не «второе значение того же токена» буквально — решение для WordPress-темы уточнить.
- Ширина `--measure-sm` заменила только `max-width` (400 / 420 / 440 / 454); `width: 400px` не трогал.
- Остались сырыми: декор (giant «okvada», «404», число 96), скругления hero 28 / 40, `border-radius: 0`, градиенты hero (rgba со значениями navy-deep / canvas), 20 / 28 / 40 px в отступах.
- `--section-system` (128) — один токен и для «снизу системных страниц», и для 404.

Проверка высот секций (iframe, до → после, 10 страниц): mobile 375 −17…0 px на страницу (из-за line-height 1.15 → 1.1); desktop 1440 −7…+2 (careers, секция 6: +9); горизонтального скролла нет. Tablet 900 изменился заметно (до +161 px на странице) — это сознательно (60 / 48 / 36 / 18 → 56 / 44 / 44 / 20, gutter 48 → 40).

## 8. Шаг 0 дизайн-системы: повторный анализ текущего кода (20 Nov, код не менялся)
